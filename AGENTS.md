# PetPals

## Architecture

A sellable TanStack Start pet-supply storefront with a libSQL (Turso / local SQLite) backend and a full admin. Routes are file-based; the storefront is rendered from database-driven homepage sections, stores its cart client-side, and talks to the server through typed server functions.

- `src/server/**` is server-only. Never import it from a route or component; call the typed server functions in `src/lib/api.ts` (public) or `src/lib/admin-api.ts` (admin) instead.
- Pages fetch through route loaders; admin pages re-run loaders with `router.invalidate()` after mutations.
- `src/routeTree.gen.ts` is generated by the TanStack Router plugin and must not be edited by hand.
- `src/server.ts` wraps the SSR handler so unexpected errors render the friendly error page instead of raw JSON.

## Brand and catalog

- Brand: **PetPals**. Poppins display/body, warm orange accent, white canvas.
- Currency **MAD**; flat shipping 50, free delivery from 500.
- Categories: `dogs`, `cats`, `foods`, `groom`, `bed`, `toys`.
- Every product is **One Size** (`SIZES` in `src/lib/checkout.ts`). Do not reintroduce apparel size guides or size selectors.
- Seed catalog: 13 products in `src/server/seed.ts`. Product photos live in `public/products/` (`bone.jpg`, `biscuit.jpg`, `bed.jpg`, `groom.jpg`); buyers replace them.
- Order numbers use the `PET-` prefix (`src/server/orders.ts`).

## Backend

- `src/server/db.ts` owns the schema bootstrap, additive column migrations, default seed (products, categories, reviews, settings, sections, pages), and runtime database switching from `/admin/setup`.
- `src/server/auth.ts` owns PBKDF2 passwords, hashed session tokens, httpOnly cookies, rate limiting and the `requireAdmin` / `requireStaff` guards.
- `src/server/catalog.ts`, `cms.ts`, `commerce.ts`, `media.ts`, `settings.ts`, `setup.ts`, `license.ts` hold the domain logic.
- Every admin mutation re-checks the session server-side and calls `requireLicense()` (a no-op unless licensing is configured).
- Prices, shipping and coupon discounts are recomputed on the server from the database. Client-supplied prices are ignored.
- Local development uses `file:.data/petpals.db`; production uses `TURSO_DATABASE_URL` + `TURSO_AUTH_TOKEN`. The buyer's DB config can also be stored server-side from Setup.
- `listProducts()` falls back to the seed catalog only when the database is unreachable; a reachable empty database renders an empty store.

## Admin and media

- `/admin` is guarded by a route loader; every admin server function re-checks the session and role. `/admin/login` is the only public admin route. A fresh database seeds the owner **`admin@email.com` / `123456789`**.
- Google OAuth is shopper-only. Staff accounts are rejected by the Google callback and must use `/admin/login`. Guest checkout is always available without any account.
- Image uploads are stored in the `media` table (≤5 MB, JPEG/PNG/WebP/GIF/AVIF) and served by `/api/media/:id` with immutable caching.
- Store the PBKDF2 hash, never plaintext, and rotate the default owner before a public launch.
- Media, settings, sections and pages are all editable; do not hard-code storefront copy that the admin is meant to control.

## Landing pages

- Homepage copy and layout live in `landing_sections`; never hard-code what the admin is meant to edit.
- A new section type needs an entry in `src/lib/cms.ts` and a case in `src/components/site/section-renderer.tsx`; the admin type dropdown and JSON config editor pick it up automatically. Add id-bearing types to the matching `save()` branch in `src/routes/admin/page-controls.tsx`.
- Keep the template sellable: Turso only, no Supabase, admin email/password, Google shopper-only, guest checkout always available.

## Finished projects and releases

- Finished stores live in `C:\Users\PC\Desktop\finished-websites\<project-slug>`; the zip goes in `finished-websites\builds\<project-slug>-source.zip`.
- Each finished store gets its own **new GitHub repo**. Never push a finished store to the design/source repo.
- Record the project, repo, zip and verification date in `finished-websites\INDEX.md`.
- **Do not rebuild zips during ordinary edits.** Build them only when the user says “zip them all” or “finish them up”.

## Conventions

- Build with Bun (`bun install`, `bun run build`).
- Keep the light-only visual language: white canvas, ink type, orange accent, Poppins.
- Run `bun run test`, `bun run typecheck`, `bun run lint` and `bun run build` before shipping.
